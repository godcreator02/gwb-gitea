## @godcreator/gwb-gitea

### 提供

| 类别 | 名字 | 说明 |
| --- | --- | --- |
| 命令 | `gitea.http` | 把一次 gitea API 调用发往设置里的实例，参数与回执见[一次调用从参数到回执](/docs/request) |
| 命令 | `gitea.push-mirror.add` | 用设置里的 GitHub token 给 gitea 上的仓开推送镜像，见[一次调用从参数到回执](/docs/request)的最后一节 |
| 服务 | `gwbGitea` | 给别的插件 inject：`http(request)` 与命令走同一个发送函数、失败抛 `Error`，`connection()` 回 `{ baseUrl, pushUrl, token }`；类型 `GwbGiteaApi` 从包入口导出 |
| 设置项 | `gitea.base-url` | 字符串，gitea 实例地址 |
| 设置项 | `gitea.token` | secret 型，gitea 的 API token |
| 设置项 | `gitea.github-token` | secret 型，GitHub token，只有 `gitea.push-mirror.add` 读；服务的 `connection()` 不交出它 |
| 设置项 | `gitea.push-url` | 字符串，和 gitea 同一台机器上的推送服务 ntfy 的地址；本插件不用，经服务的 `connection()` 交给 gwb-collab |
| 说明书 | `gitea` | `skills/gitea/SKILL.md`，随包发布 |

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需（`export const inject`） | `^0.6.0` | 登记 `gitea.http` 与 `gitea.push-mirror.add` | 插件不加载 |
| `gwbSettings` | `@godcreator/gwb-settings` | 必需（`export const inject`） | `^0.4.0` | 声明四项设置，每次调用读地址与 token | 插件不加载 |
| `gwbSkills` | `@godcreator/gwb-skills` | 局部注入（`ctx.inject`） | `^0.4.7`，标记为 `optional` | 登记 `skills/` 目录 | 命令照常可用，`skill.list` 里没有 `gitea` |

内核包 `@godcreator/gwb-kernel-desktop` 也写在 peer（`^0.10.0`），只取 `GwbContext` 这类类型；插件不用 `gwbKernel`。
这几个包都只 `import type`，编译后整句消失。`cordis` 也写在 peer（`^4.0.0-rc.10`），由宿主提供，服务类继承它的 `Service`，
所以产物里按包名 import 的只有 node 内置模块和 `cordis`。

服务 `GiteaService` 只存发送和读设置两个闭包，不存 `gwbSettings`：cordis 读服务属性时，会把属性里存的服务换成调用方上下文里的那份，
调用方没 inject `gwbSettings` 就读到 undefined。

说明书目录的地址按产物位置算：`dist/index.js` 的上一级就是 `skills/`，不写死磁盘路径。说明书插件只扫这个目录下的子目录，
所以一份说明书一个子目录（`skills/gitea/SKILL.md`），直接放在 `skills/` 下的 `SKILL.md` 会被跳过、也不报错。

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 网络 | gitea 实例 | `<base-url>/api/v1/…` | 发出 `gitea.http` 与 `gitea.push-mirror.add` 的调用 |
| 文件 | 本机磁盘 | 参数里的 `file.path` | 读要上传的文件 |

不按名字调用别的插件的命令。

## @godcreator/gwb-gitea-issues

### 提供

| 类别 | 名字 | 说明 |
| --- | --- | --- |
| 命令 | `gitea-issues.list`、`gitea-issues.detail`、`gitea-issues.status` | 都是 `read`，见[gwb-gitea-issues](/docs/issues) |
| 窗格 | `issues` | 工具窗格「issue 与合并请求」 |
| 设置项 | `gitea-issues.owners`、`gitea-issues.poll-minutes` | 看哪些 owner、多久查一次 |

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需 | `^0.6.1` | 登记三条命令 | 插件不加载 |
| `gwbSettings` | `@godcreator/gwb-settings` | 必需 | `^0.4.0` | 声明并读两项设置 | 插件不加载 |
| `gwbData` | `@godcreator/gwb-data` | 必需 | `^0.1.12` | 数据目录里存上次看到的状态 `seen.json` | 插件不加载 |
| `gwbGitea` | `@godcreator/gwb-gitea` | 必需 | `^0.1.17` | 经 `http` 查 issue、合并请求与评论 | 插件不加载 |
| `timer` | `@cordisjs/plugin-timer` | 必需 | `^1.1.3` | 定时查新内容 | 插件不加载 |
| `gwbShell` | `@godcreator/gwb-shell` | 局部注入，`optional` | `^0.15.11` | 登记窗格 | 没有窗格，命令与推送照常 |
| `gwbQqBot` | `@godcreator/gwb-qq-bot` | 局部注入，`optional` | `^0.8.0` | `notify` 私聊主人 | 不推送，`status` 里 `qqBotAvailable` 是 false |

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 文件 | 本插件数据目录 | `seen.json` | 上次看到的每条 issue 与合并请求的评论数 |

不按名字调用别的插件的命令，也不直接连网络：访问 gitea 都经 `gwbGitea.http`。
