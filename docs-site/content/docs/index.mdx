# gitea 的手

**本页回答**：`gwb-gitea` 是什么、一次调用怎么走、从哪一页开始读。

怎么走到今天去 [轨迹](/trajectory)，还没发生的事在 [未来](/future)。

## 是什么

gwb 工作台里调 gitea API 的插件，只有一条命令 `gitea.http`：agent 组装好一条 gitea API 调用，插件把它发往
设置里配的那个 gitea 实例。建仓、发 release、传产物这些用法全写在随包发布的说明书 `gitea` 里，代码只负责
把请求原样发出去，不另设建仓命令、发版命令。

## 一次调用怎么走

`src/core.ts` 的 `parseArgs` 先收窄参数，`buildUrl` 补上 `/api/v1` 前缀与 query；`src/index.ts` 的 handler
取设置里的 token 放进 `Authorization`，有 `file` 参数就按 multipart 上传，发出请求后交给 `shapeResponse`
整理成 `{ status, truncated, body }`。2xx、4xx、5xx 都算发出去了，由调用方解释；只有请求没发出去才回
`ok: false`，报错里的 token 经 `redact` 脱敏。
