# gitea 的手

**本页回答**：`gwb-gitea` 是什么、解决什么问题、从哪一页开始读。

这一区只写**现状**：设计、原理、边界、接口——散文，不写历史，不写计划。为什么变成这样去
[轨迹](/trajectory)，往哪儿去看 [未来](/future/overview)，正在做的活在 [交接](/spec)。
写法的判据见随 `@godcreator/docfirst-workflow` 发的 skill「docfirst-docs」，这儿只留一句：
**一句话如果能被代码推翻，它就该带引用；一句话如果只是在复述代码，它就不该存在。**

## 第一条引用

下面这块不是抄进文档的副本，是构建那一刻从源码现拿的：

@@docfirst ref ../src/index.ts:10-10 @@

上面那行是**草稿记号**。先落一个提交，再在这个目录跑 `pnpm doc:confirm`，它会被换成正式
记号、状态点转绿——git 比较器只对已提交、工作区干净的内容钉。

<Note>
  这一段在站上是提示框，在机读版里是引用块。压平规则住格式包的默认表里，站只提供画框的组件。
  自己加组件要**两头都登记**：React 那半进 `src/components/`，压平规则进 `docfirst.config.mjs`，
  `pnpm verify:roster` 守着两头齐。
</Note>

## 这一区怎么长

[系统地图](/docs/system-map) 是总索引：拆成哪几块、各住哪、依赖方向、先读哪块。每块一页，
页里是固定块（管什么 / 不知道什么 / 数据结构 / 提供的接口 / 依赖的接口 / 怎么单独测 / 代码地图），
接口与边界逐条钉住。[术语表](/docs/glossary) 收这个仓里的词。

只写「错了难改」的：边界约束、依赖方向、接口契约、状态机、取舍。实现者剩下的自由度里
做任何选择都不违背这一区，就够了。
